# Полный цикл

1. Определить московскую дату и рабочую папку дня; проверить отсутствие другого исполнителя. Прочитать живые сотрудники, критерии, существующие ID в реестре и отчёте. Сопоставить соответствующую локальную книгу с Google по содержанию. Содержательный конфликт сохранить; спорные поля не переносить автоматически.
2. Сделать снимок значимых значений, формул, примечаний, структуры и оформления до записи. Коллектор использует московский интервал [00:00, следующая 00:00), CALL_FAILED_CODE=200, типы 1/2 и >=60 секунд. Проверить пагинацию и полный состав ID. Неоднозначные имена требуют уточнения; не разрешать частичное сопоставление для полного цикла.
3. Скачать записи через download_calls.py. Проверить сигнатуру аудио, размер и SHA256. Отдельно учесть звонки без доступной записи/ошибки. Имена: дата-время-сотрудник-ID. CRM брать из конкретного звонка/CRM activity, не по телефонному совпадению.
4. Через Drive-коннектор найти/создать папку даты, загрузить недостающие файлы. При повторе проверить ID/имя/размер, а не загружать снова. Записать реальные Drive ID/URL в manifest после завершения скрипта, перечитать папку, сверить полный набор. Не считать успешный HTTP скачивания успешной загрузкой на Drive.
5. collect_transcripts.py читает существующие транскрибации Bitrix24. Не запускает платный AI и не меняет CRM. Для остальных — локальный Whisper medium. Скрипт сохраняет manifest после каждого звонка; другие писатели должны ждать его завершения.
6. Проверить тексты: пропуски длинных участков, пустой/слишком короткий текст, повторяющиеся фразы и сомнительное окончание требуют повторной расшифровки без VAD/батчинга либо конкретного аудиофрагмента. Сохранить оригинал и источник исправления. «Готово» не доказывает полноту распознавания. При сомнениях не выставлять недоказанные оценки.
7. Реестр: ID, дата, время МСК, сотрудник, направление, входящий/исходящий, секунды, статус загрузки, ссылка на аудио, CRM ссылка, **полный текст**, источник/статус текста, примечание, имя файла. ID — основной ключ; сортировка по времени, не считать порядок ID хронологией. Существующую native table сохранять. Даты писать числовым serial с форматом даты или проверенным API способом: Date-объект при XLSX-импорте раньше давал пустые даты. Проверять formattedValue и hyperlink; ошибка рендера HYPERLINK не равна ошибке Google.
8. Агент читает полные тексты и текущую шкалу, формирует отдельный файл оценок: call_id, type, scores|null, comment, evidence, uncertainty, order_amount|null. Отсутствующие суммы заказа не придумывать. Применить методику assessment.md.
9. Добавить только отсутствующие ID в соответствующие блоки продаж/сервиса/опроса. **Не копировать индексы колонок и номера строк прежних дней**: найти текущие заголовки блоков, критерии, последнюю занятую колонку. При вставках справа выполнять их от правого блока к левому. Сохранить существующие формулы, критерии и историю. Проверить диапазоны итогов и сводок.
10. Заполнить «Проверка звонков» по фактическим полям: финнеделя по существующей схеме, дата звонка, реальная дата проверки, направление, сотрудник, тип, CRM/аудио, итог в долях для %, соответствие, комментарий, формула необходимости обучения по существующему шаблону, краткий вывод. Не переносить 14.10 или фиксированные даты автоматически на будущие недели. При неизвестной финнеделе спросить пользователя. Не считать шаблонные формулы ниже таблицы занятыми проверками.
11. Перечитать записанные диапазоны: все ID ровно один раз, даты, ссылки, типы, баллы в пределах шкалы, суммы/статусы, формулы, отсутствие новых ошибок; сравнить прежние данные с снимком. Проверить формат % и читаемость комментариев. AutoResizeRows иногда не увеличивает высоту: проверить экспорт/рендер и исправить только новые строки.
12. Экспортировать native Google XLSX для соответствующей локальной рабочей копии, сохраняя формулы/вычисленные значения. Для авторинга XLSX использовать доступный spreadsheet runtime, не переписывать книгу библиотекой, теряющей формулы/кэши. Сверить значимые данные всех листов; известные нерешённые конфликты исключать точечно и документировать, не выбирать одну версию целиком.
13. Сохранить manifest, основания оценок и краткую проверку полноты. Актуализировать тематический контекст в рамках поручения; синхронизировать найденную соответствующую Drive-версию. Сообщить фактические количества, ссылки и незавершённые проверки.

При изменении структуры отчёта остановить только запись, сохранить сбор/тексты и подготовить новый план диапазонов. При ошибке доступа не менять права автоматически. При сетевой ошибке чтения допустимы до трёх попыток; перед повтором внешней записи перечитать результат, чтобы не создать дубль. Если восстановление невозможно, назвать незавершённый этап. Установка скилла не разрешает запускать новый день без поручения/настроенного расписания.
