# Активность сотрудника по закреплённым компаниям

Результат — автономный интерактивный HTML для операционного анализа. Сотрудник может быть менеджером, специалистом, сервис-менеджером или иметь другую должность. Не закрепляй имя, ID, даты или показатели предыдущего примера в алгоритме.

## Параметры и границы

Определи сотрудника и точный ID, период включительно и часовой пояс (для MaterLux — Europe/Moscow, если пользователь не указал другой). При неоднозначной учётной записи уточни её до выгрузки. Повторно не спрашивай уже согласованные параметры.

Битрикс24 — только через защищённый REST-вебхук. Не использовать браузер портала, авторизацию браузерной сессии или альтернативное подключение. В MaterLux подключение описано в проектном AGENTS.md; защищённый файл — `C:\Users\User\AppData\Local\MaterLux-Bitrix24\webhook.xml`, скрипты — `Интеграция Битрикс24` проекта. Проверяй доступность методов отдельно от наличия файла. Не печатай URL/ключ, расшифрованный секрет, тела ошибок с секретом; секрет не включать в HTML, исходники или журналы. В другом проекте используй его разрешённый защищённый способ доступа, не переноси реквизиты MaterLux.

Навык разрешает чтение и создание отдельного локального результата в рамках поручения. Не изменять CRM, переписку, отметки прочтения, вебхуки, права или настройки. Не публиковать результат и не отправлять другим людям без соответствующего поручения. При недоступном методе назвать конкретное ограничение, не обходить его интерфейсом.

## Отбор компаний — обязательный инвариант

1. Получи полный актуальный список компаний, у которых `ASSIGNED_BY_ID` равен ID выбранного сотрудника. Зафиксируй время проверки. Это **текущая принадлежность**, не историческая ответственность в периоде.
2. Найди контакты этих компаний, независимо от ответственного контакта. Действия выбранного сотрудника по ним относятся к компании. Получи минимальные связи сделок, необходимые для отнесения активности/комментариев к компании.
3. Одна строка отчёта — одна компания из этого списка. Контакт никогда не отдельная строка. Исключить контакты без компании, компании других ответственных и действия по ним, даже если сам контакт закреплён за выбранным сотрудником.
4. Не определяй компанию по похожему названию/телефону. Противоречивые и множественные связи, не позволяющие однозначно отнести событие, выдели как нераспределённые; не размножай одно событие по компаниям.

## Сбор и нормализация

Перед реализацией сборщика прочитай [техническую памятку](references/collection-and-validation.md). Используй существующие проверенные локальные средства чтения; не выгружай полные карточки, если достаточно ID, имени и связей.

Собери за период звонки, письма, доступные отправки кампаний, переписку открытых линий/Whazzup и собственные комментарии по компаниям, их контактам и связанным сделкам. Точное авторство, направление, время и компания проверяются по источнику. Ответственный дела/карточки сам по себе не доказывает автора действия. Пометка Whazzup с именем сотрудника может подтвердить автора; числовой ID технического отправителя интеграции — нет. Основание авторства сохраняй для раскрытия записи. Неподтверждённые действия не приписывать сотруднику.

Период обрабатывай как `[начало первого дня; начало дня после последнего)` в выбранном часовом поясе. Удаляй повторы одного события, отражённого в нескольких объектах или источниках. План, напоминание, задача или её зеркало не являются выполненным касанием.

| Тип | Правило |
|---|---|
| Исходящий звонок | Один уникальный звонок — одно касание, включая неуспешный дозвон. Разговор / попытка / неизвестный исход показывать раздельно. Длительность разговоров суммировать по подтверждённому полю, не по времени существования CRM-дела. |
| Исходящее письмо | Одно подтверждённое отправленное сотрудником письмо — одно касание после удаления дублей. |
| Диалог | Одна компания + один календарный день + наличие подтверждённого исходящего сообщения сотрудника = одно касание. Объединять сообщения всех контактов этой компании и всех доступных каналов. |
| Рассылка | Отдельно учитывать только подтверждённую отправку кампании компании с доказанным участием сотрудника. Рекламный текст не доказывает кампанию. Сообщение, уже учтённое в диалоге, не считать повторно. |
| Комментарий | Каждый уникальный собственный внутренний комментарий сотрудника — отдельная запись в общем показателе; явно подписывать «внутренний комментарий». |
| Входящее | Отдельный показатель входящего потока этих компаний: звонки, письма, дни входящих диалогов. В исходящие не прибавлять; не представлять как выполненную сотрудником работу. |

Ответ сотрудника клиенту входит в исходящие. Для диалогов при доказательствах различать самостоятельную инициативу, ответ на обращение, смешанный случай и неизвестную инициативу. Входящее и исходящее общение в один день могут отображаться в обоих раздельных показателях. Тему/характер определять только по доступному содержимому; без текста или расшифровки тема звонка неизвестна. Автоматическую тематическую классификацию обозначать как классификацию, не как установленный результат разговора.

Ноль, неизвестность и недоступность — разные состояния. Ноль писем в проверенном CRM-учёте не доказывает отсутствие писем во внешней почте. Неподтверждённую полноту рассылок показывать прочерком и объяснением. Сообщить, какого доступа не хватает для конкретного канала, не менять его самостоятельно.

## Дашборд и выдача

- Показывать сотрудника, период, дату выгрузки/проверки компаний, правила и ограничения. Основная таблица: компания со ссылкой CRM; исходящие всего; звонки и их три исхода; длительность разговоров; письма; рассылки; дни диалогов; внутренние комментарии; входящие отдельно.
- Фильтры: компания и тип касания. По умолчанию сортировка исходящих по убыванию, с возможностью смены направления и столбца. Флажок для компаний без активности; число компаний с исходящими отличать от числа с любой активностью.
- Фильтр пересчитывает таблицу, сводку, раскрываемые записи и CSV согласованно. Нажатие числа раскрывает только соответствующие касания с датой, исходом, доступной темой/текстом, основанием авторства и ссылками. Выбранную строку подсвечивать.
- Название открывает компанию; звонок — проверенное дело звонка в CRM. Не выдавать ссылку на компанию за проверенную прямую ссылку на чат. Наличие CRM-ID/корректного href и фактическое открытие страницы — разные проверки; браузером портал не проверять.
- Не выводить полные карточки, хронологию задач и технические снимки. HTML автономный, без вебхук-секрета и внешней отправки данных; экранировать тексты источников. CSV отражает выборку и защищает текстовые ячейки от исполнения формул.
- В выдаче один явно обозначенный актуальный HTML, например `ОТКРЫТЬ — Активность компаний__Сотрудник__Период.html`. Данные, код и проверки — в технической подпапке. Не оставлять несколько равноправных HTML-кандидатов. Старые пользовательские результаты не удалять/перемещать без разрешения; новый результат можно сохранить отдельно. Статус черновика указывать в методике, не объявлять корпоративным утверждением.

## Приёмка

Сверь исходные записи и суммы по типам; только допустимые company ID; ноль контактных строк; уникальные source ID; отсутствие повторов дневного диалога компании; непересечение исходящих и входящих в общем счётчике. При пересборке покажи сверку «до − исключено = после»; переиспользование старой выгрузки явно обозначь и отдельно проверь актуальность списка компаний.

В браузере **локального HTML** проверь пересчёт фильтров, сортировку, пустую выборку, флажок нулевых компаний, подсветку, раскрытие числа записей, href и CSV; проверь ошибки JavaScript. Программная проверка не заменяет визуальную. Если среда не позволяет проверить интерфейс, сообщи это и не называй его проверенным. Заверши краткой ссылкой на единственный актуальный HTML, итогами и существенными ограничениями; не сообщай выдуманный расход токенов или время.
