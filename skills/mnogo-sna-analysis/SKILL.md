# Анализ «Много сна»

Работай в пределах текущего поручения: прайс, география отгрузок, ПЭК или их сочетание. Не запускай остальные этапы автоматически. Правила проекта и последние ответы Ирины имеют приоритет над историческим примером.

## До расчётов

1. Прочитай действующие правила проекта и релевантный контекст. Определи источники, период, место результата и разрешённые изменения. Источники сохраняй неизменными; текущий дашборд обновляй только при соответствующем поручении.
2. Назови существенные вопросы до преобразования данных: знаменатель доли, граница ширины, дата для месяца, адрес доставки и режим ПЭК. Не спрашивай повторно уже согласованное.
3. Проверь заголовки и видимость листов. Не извлекай содержимое скрытых листов. Скрытые строки группировки внутри разрешённого видимого листа — другая вещь: не исключай их автоматически из товарных итогов.
4. Для чисел и независимых сверок используй Python. Сохрани происхождение значений: файл, видимый лист, строка/ячейка, дата проверки.

Подробный алгоритм и развилки: [references/algorithm.md](references/algorithm.md). Источники, решения и результаты сессии 12.10.2026: [references/session-2026-10-12.md](references/session-2026-10-12.md). Это исторический снимок, не актуальные тарифы и не нормативы на следующий период.

## Обязательные инварианты

- Прайс: точное соответствие «модель + ширина + длина»; колонка **«Себестоимость с учетом отходов»** определяется по заголовку, не по букве. Доля = себестоимость / исходная цена. Это не маржа. Неясное соответствие названий согласуй, а не угадывай.
- Отгрузки: учитывай только товарные строки. Не суммируй вместе итог дня, итог заказа и его товары. Количество и выручку бери из отгрузок; адрес — из заказов по нормализованному номеру. Строки без показателей не заменяй нулём и не дополняй из суммы заказа.
- Регион: Москва + область и Петербург + Ленинградская область — два отдельных объединённых сегмента. Остальные субъекты — по подтверждённому адресу. Порог ширины: **120 см включительно** в первой группе. Месяц — по дате отгрузки.
- ПЭК: используй **реальный населённый пункт** адреса, не административный центр. Проверяй сдачу в отделении Москвы и получение **по адресу**, а не на терминале. Несколько городов региона требуют разных тарифов и суммирования по фактическому количеству.
- Обновлённые данные, новые источники и изменение параметров требуют новой сверки. Подключение к сайту само по себе не подтверждает состав тарифа.

## Файл критической проверки

Перед выдачей численного результата запускай [scripts/critical_check.py](scripts/critical_check.py) с манифестом конкретной задачи. Он сам читает разрешённые листы исходных XLSX и данные готового HTML, не импортирует код построителя, не делает сетевых запросов и не изменяет исходники.

```powershell
& '<Python из load_workspace_dependencies>' '<путь навыка>\scripts\critical_check.py' --manifest '<манифест задачи.json>'
```

[references/session-manifest.json](references/session-manifest.json) настроен на сегодняшние файлы и используется как проверочный пример. Для другого периода подготовь отдельный манифест в рабочей папке задачи; не перезаписывай исторический пример. `--expect-snapshot` дополнительно сверяет контрольные числа именно сессии 12.10.2026.

Проверка устроена в два уровня:

1. **Независимые численные проверки**: исходные хеши, модель/размер/цена/формула, номера/адреса, количество/выручка, дни/заказы/месяцы, ширина/регион, параметры ПЭК, состав тарифа, доставка по городам и исключённые регионы.
2. **Ручные условия выдачи**: подтверждение валюты, реальное открытие Excel без восстановления, визуальная проверка HTML и живой тариф ПЭК. Скрипт не способен подтвердить их автоматически; он выводит отдельные предупреждения. `NUMERIC_PASS` не означает, что всё проверено в Excel, браузере или у перевозчика.

Если есть `FAIL`, исправь причину или останови зависимый расчёт с конкретным вопросом. При неполных исходных данных показывай исключения и ограничение вывода. Не превращай предупреждение в скрытый ноль, успешную проверку или утверждение о фактической оплате доставки.

## Выдача

Покажи результат, путь, проведённые проверки и оставшиеся ограничения. В дашборде тарифы должны иметь дату, параметры и статус «предварительный расчёт». Исторические количества × текущие тарифы — оценка расходов, не доказательство фактических затрат. Программный тест пересчёта не называй визуальной проверкой браузера. Не обещай автоматические обновления: навык запускается при соответствующей работе.
